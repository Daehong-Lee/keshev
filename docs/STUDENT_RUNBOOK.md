# 케셰브 학생용 실행 설명서와 구성도

이 문서는 현재 저장소의 `on-client/` 앱을 실행하고, 구성과 제공·학생 작성 코드의 경계를 확인하는 안내입니다. 기존 안내서를 대체하지 않습니다. 단계와 포털 제출 절차는 ALEPH 과제 화면의 최신 안내를 우선합니다.

## 1. 앱 목적과 지원 환경

케셰브는 사용자가 본인 로그인 상태, 업무 앱의 접근 판정, 보안 기록을 확인하는 로컬 웹 앱입니다. 학생이 구현하는 화면 표시는 `student/extension.mjs`에 있고, 앱 서버와 공통 화면·연결 코드는 시작 틀에서 제공합니다.

| 항목 | 현재 저장소에서 확인한 내용 |
|---|---|
| 앱 작업 폴더 | `on-client/` — `package.json`, `src/`, `public/`, `student/`, `tools/`, `docs/`가 있는 폴더 |
| Node.js 기준 버전 | `package.json`의 `engines.node`는 `24.19.0`; 실행 도구는 22~24를 허용하고 24.19.0을 기준으로 안내 |
| 실제 설치 버전 | 이 작업에서는 `node --version`을 실행하지 않았으므로 미확인 |
| npm 의존성 | `package.json`에 `dependencies` 또는 `devDependencies`가 선언되어 있지 않음 |
| lockfile | 현재 파일 목록에서 `package-lock.json`을 확인하지 못함 |
| 실행 방식 | Windows PowerShell 실행 도구(`tools/start-alekov.ps1`) 또는 `package.json`의 npm 스크립트 |
| 실제 접근 제어/XDR | 기본 실행은 미연결입니다. 담당자가 제공한 지원 설정이 있는 경우에만 별도 연결을 구성합니다. |
| 브라우저 | 이 문서는 로컬 브라우저 실행만 안내합니다. 특정 브라우저·운영체제에서 실제 호환성 시험을 했다는 뜻은 아닙니다. |

```text

├── package.json                   start / demo / check, Node.js 기준 버전
├── tools/
│   └── start-alekov.ps1           Node·폴더·포트 확인 후 로컬 서버 시작

│   ├── engine.mjs                 연결 엔진 로딩 및 예제 엔진
│   ├── ai/                        앱 권한·AI 서비스·연결 모듈
│   └── vulnerabilities/           lockfile·설치 메타데이터·OSV 조회
├── public/
│   ├── index.html                 제공 화면 골격 및 학생 표시 영역

│   └── style.css                  제공 스타일
├── student/
│   ├── extension.mjs              학생 구현 표시 함수
│   └── engine-adapter.mjs         호스트 기능 전달을 위한 어댑터 경계
└── docs/                          학생·운영 안내 문서
```

## 2. 실행, 정상 시작 신호, 종료와 재실행

### 실행 전 준비

1. 파일 탐색기에서 실제 프로젝트의 `on-client/` 폴더를 엽니다. 이 폴더에는 `package.json`과 `tools/start-alekov.ps1`이 있어야 합니다.
2. 폴더 주소 표시줄에 `powershell`을 입력하고 Enter를 눌러 **그 폴더를 현재 위치로 한 새 PowerShell 창**을 엽니다. 프로젝트 바깥 폴더나 바로가기 위치에서 실행하지 않습니다.
3. Node.js 기준 버전은 24.19.0입니다. 실행 도구는 22~24도 허용하지만, 다른 버전으로 실행할 경우 화면에 기준 버전 안내가 나올 수 있습니다.
4. 프로젝트의 기존 파일이나 작업을 지우거나 초기화하지 않습니다. 이 앱의 `package.json`에는 npm 패키지 설치 항목이 선언되어 있지 않으므로 이 실행 절차에서는 `npm install`을 요구하지 않습니다.

### 선택 검사와 서버 시작

먼저 선택적으로 학생 모듈의 문법 검사를 할 수 있습니다.

```powershell
npm run check
```

이 스크립트는 `node --check student/extension.mjs`만 실행합니다. 서버 시작이나 브라우저·API·외부 서비스의 동작을 검사하지 않습니다.

같은 PowerShell 창에서 기본 실행 명령을 입력합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

실행 도구는 앱 폴더, Node.js 버전, 기본 포트 5189의 사용 여부를 확인한 뒤 `src/server.mjs`를 시작합니다. `-ExecutionPolicy Bypass`는 이 명령 실행에만 적용됩니다. 컴퓨터의 실행 정책을 영구 변경하는 절차가 아닙니다.

정상 시작 신호는 실행 도구가 다음과 비슷한 문구를 출력하고 서버가 응답하는 것입니다.

```text
케셰브가 켜졌습니다. 브라우저에서 http://127.0.0.1:5189/ 을 여세요.
서버가 응답한 것만 확인했습니다. AI 연결 상태는 화면에서 따로 확인해 주세요.
```

브라우저에서 다음 주소를 엽니다.

```text
http://127.0.0.1:5189/
```

`5189`가 다른 프로그램에서 사용 중이면 그 프로그램을 종료하지 말고 다음과 같이 다른 포트를 지정합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5190
```

이 경우 브라우저 주소도 `http://127.0.0.1:5190/`로 바꿉니다. 포트가 다른 숫자라면 출력된 주소의 포트를 사용합니다. 시작 도구가 서버 응답을 확인했다는 사실은 실제 회사 시스템이나 AI 게이트웨이에 연결됐다는 뜻이 아닙니다.

### 예제 실행

화면 형태를 예제 데이터로 보려면 실행 도구에 `-Demo`를 추가할 수 있습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo
```

또는 현재 `package.json`의 스크립트로 실행할 수 있습니다.

```powershell
npm run demo
```

예제는 실제 사용자·기기·접근 제어/XDR 기록이 아니며 실제 연결 성공이나 과제 성취를 나타내지 않습니다. `-Demo`와 `-SdpHostConfig`는 함께 사용할 수 없습니다.

### 종료와 재실행

- 기본 실행은 실행 중인 PowerShell 창에서 `Ctrl+C`로 종료합니다.
- 종료 후 같은 `on-client/` 폴더에서 동일한 실행 명령을 다시 입력하면 재실행됩니다. 재실행은 프로젝트 파일을 바꾸지 않습니다.
- 실행 도구의 `-Background` 옵션은 서버를 창 없이 실행합니다. 이 경우 도구가 출력한 프로세스 번호를 기록하고, 종료할 때 작업 관리자에서 그 번호에 해당하는 `node` 프로세스를 종료합니다. 처음 확인할 때는 종료가 분명한 기본 실행을 권장합니다.

## 3. 글로 쓴 시스템 구성도

```text
[사용자 브라우저]
  public/index.html · public/app.js · student/extension.mjs의 표시 영역
        │ 같은 출처의 HTTP 요청 (기본 주소 http://127.0.0.1:5189/)
        ▼
[이 PC의 Node.js 앱 서버: src/server.mjs]
  ├── 기본 실행: 연결 엔진 없음(disconnected)
  │       └── 담당자 설정이 제공된 경우에만 호스트 어댑터를 통해
  │           접근 제어·XDR 시스템과 본인 범위의 자료를 주고받음
  ├── 앱 AI 기능(별도 권한·연결 필요)
  │       └── 앱 서버의 AI 모듈 → 설정된 AI 게이트웨이
  │           → AI 응답이 서버를 거쳐 앱으로 돌아옴
  └── 패키지 조회(사용자가 조회를 요청한 경우)
          └── 서버의 OSV 스캐너 → https://api.osv.dev/v1/querybatch
              package-lock.json 및 설치 메타데이터와 대조한 결과를 앱에 전달
```

이 구성은 코드에서 정의한 관계이며 외부 서비스가 현재 접속 가능하거나 계정 권한이 준비됐다는 확인이 아닙니다. 기본 엔진은 `src/engine.mjs`에서 미연결 상태로 구성됩니다. 예제 엔진은 `--demo`로 선택할 때만 사용합니다. 접근 제어/XDR 연동은 담당자가 준비한 호스트 설정이 있어야 하며, AI 앱 연결도 앱 전용 권한과 운영 설정이 필요합니다. 브라우저의 서버 응답만으로 이러한 연동을 성공으로 판정하지 않습니다.

코드에 정의된 공개 서비스 주소는 다음과 같습니다. 주소가 코드에 있다는 사실과 네트워크 연결 성공은 구분해야 합니다.

| 용도 | 코드에 있는 주소 | 실제 연결 상태 |
|---|---|---|
| 기본 로컬 앱 화면 | `http://127.0.0.1:5189/` | 실행 도구가 로컬 HTTP 응답을 확인하도록 작성됨. 이 작업에서는 실행하지 않음 |
| OSV 조회 API | `https://api.osv.dev/v1/querybatch` | `src/vulnerabilities/osv.mjs`의 기본 주소. 실제 외부 요청은 미실행 |
| 포털 승인 흐름 | `https://aleph-omega.vercel.app` | `src/ai/connection.mjs`의 포털 출처. 로그인·승인 성공은 미확인 |
| 앱 연결 게이트 기본 출처 | `https://ai-classroom-gateway-production.up.railway.app` | 같은 연결 모듈의 기본 출처. AI 응답 또는 서비스 가용성은 미확인 |

## 4. 제공 코드와 학생 작성 코드의 경계

| 영역 | 실제 파일·함수 또는 화면 이름 | 역할 및 경계 |
|---|---|---|
| 학생 구현 | `student/extension.mjs`: `renderIdentity`, `renderStatus`, `renderAiConnection`, `renderVulnerabilities`, `renderDecision`, `renderEvents`, `renderExplanation`, `renderAction` | 학생 화면의 표시 구현입니다. `public/index.html`의 학생 구현 영역에 각 이름이 표시됩니다. |
| 제공 브라우저 UI | `public/index.html`, `public/app.js`, `public/style.css` | 화면 골격, 브라우저 이벤트 및 제공 UI입니다. 단계 과제에서 지정하지 않았다면 수정하지 않습니다. |
| 제공 로컬 서버 | `src/server.mjs`: `createOnServer` 및 서버 시작부 | 로컬 HTTP 서버와 API를 제공합니다. 학생 UI와 호스트 기능 사이의 서버 경계입니다. |
| 엔진 연결 경계 | `src/engine.mjs`: `loadEngine`, `demoEngine`; `student/engine-adapter.mjs`: `createEngine` | 연결 어댑터를 로드하거나 예제 엔진을 제공합니다. 학생 어댑터는 호스트가 제공한 기능을 전달하는 경계이며, 그 자체가 운영 XDR 서버나 권한을 제공하지 않습니다. |
| 제공 패키지 조회 | `src/vulnerabilities/project-scan.mjs`: `createProjectScanner`; `src/vulnerabilities/osv.mjs`: `buildPackageQueries`, `createOsvClient` | 운영자 설정과 프로젝트 메타데이터를 바탕으로 공개 승인 패키지를 OSV와 대조합니다. 미조회·일부 실패는 취약점 없음과 다릅니다. |
| 제공 AI 기능 | `src/ai/service.mjs`: `createOnAiService`; `src/ai/connection.mjs`: `createAlekovAppConnector` | 앱 전용 권한·연결을 처리하는 제공 코드입니다. 성공 여부는 실제 권한과 게이트 응답이 있어야 확인할 수 있습니다. |

제공 파일의 존재나 함수 이름만으로 해당 외부 시스템이 구성·운영 중이라고 단정하지 않습니다. 토큰, 비밀번호, 개인키, 인증서, 비밀 설정값을 이 문서나 저장소에 기록하지 않습니다. 담당자가 별도 설정 파일을 안내한 경우 프로젝트와 Git 바깥의 지정 위치에 보관하고, 실제 옵션과 경로는 담당자 안내를 따릅니다.

## 5. 오류별 확인·복구 순서

| 증상 또는 코드 | 순서대로 확인할 내용 | 안전한 복구 방법 |
|---|---|---|
| `Node.js 가 없습니다` 또는 버전 안내 | 새 PowerShell에서 Node.js가 설치되어 있는지, 실행 도구가 허용하는 버전(22~24)인지 확인합니다. | 기준 버전 24.19.0을 설치한 뒤 PowerShell 창을 새로 열어 재실행합니다. 이 작업에서 설치 상태는 확인하지 않았습니다. |
| 포트가 이미 사용 중이라는 안내 | 다른 프로그램이 기본 포트 5189를 사용 중인지 확인합니다. 실행 도구는 그 프로세스를 종료하지 않습니다. | `-Port 5190`처럼 다른 포트로 시작하고 브라우저 주소도 그 포트로 바꿉니다. |
| 앱 폴더 또는 파일을 찾지 못함 | 현재 폴더가 `package.json`과 `tools/start-alekov.ps1`이 있는 실제 `on-client/`인지 확인합니다. 바로가기 경로가 아닌지 확인합니다. | 파일 탐색기에서 실제 `on-client/` 폴더를 열고 주소 표시줄에서 새 PowerShell을 엽니다. |
| 서버 시작 대기 시간 초과 또는 브라우저에서 로컬 주소를 열 수 없음 | PowerShell의 전체 오류와 실행이 끝났는지 확인하고, 브라우저 포트가 실행 명령의 `-Port` 값과 같은지 확인합니다. | 기존 작업을 지우지 말고 오류 내용을 보존합니다. 원인을 모르면 담당자에게 오류 문구를 전달합니다. 실행 도구의 기본 대기 시간은 20초이며 `-WaitSeconds`로 조정할 수 있습니다. |
| `ENGINE_NOT_CONNECTED`, `disconnected` 또는 예제 상태 | 기본 실행인지 `-Demo` 실행인지 확인합니다. 기본 미연결 및 예제 상태는 실제 접근 제어/XDR 연결이 아닙니다. | 임의로 설정을 만들거나 경로·허용 대상을 바꾸지 않습니다. 담당자가 실제 연결 설정을 제공했는지 확인합니다. |
| AI 준비·권한·게이트 오류 | 화면의 원래 오류 코드와 `docs/CONNECTION_TROUBLESHOOT.md`의 AI 연결 항목을 확인합니다. 서버 시작 신호와 AI 연결을 혼동하지 않습니다. | 운영자에게 앱 전용 권한·계정 연결 상태를 확인합니다. 열쇠나 비밀번호를 복사하거나 공유하지 않습니다. |
| 패키지 조회가 `not_configured`, `not_checked`, `partial` 또는 `unverifiable` | 오류 코드와 조회 상태를 구별하고 `docs/CONNECTION_TROUBLESHOOT.md` 및 `src/vulnerabilities/README.md`의 안내를 확인합니다. | 대상 경로나 승인 목록을 학생이 임의로 바꾸지 않습니다. 조회 실패·미조회는 취약점 없음이 아닙니다. |

## 6. 이 작업에서 확인한 것과 미확인인 것

| 확인 항목 | 상태 | 근거 또는 미확인 사유 |
|---|---|---|
| 실행 명령·포트·브라우저 주소 | 코드 판독 | `package.json`, `tools/start-alekov.ps1`, `src/server.mjs`를 읽어 문서에 반영했습니다. 실제 명령 실행은 하지 않았습니다. |
| 지원 함수 이름과 제공/학생 영역 | 코드 판독 | `public/index.html`의 학생 영역 이름과 파일 구조를 기준으로 정리했습니다. 실제 브라우저 표시는 확인하지 않았습니다. |

| 브라우저 화면·포트 충돌·오류 복구 | 미확인 | 브라우저 제어와 로컬 명령 실행을 이 도구에서 수행할 수 없음 |
| 실제 접근 제어/XDR 연결 및 AI 게이트 연결 | 미확인 | 담당자 설정, 계정 권한, 외부 연결을 시험하지 않음 |
| 실제 OSV 조회와 패키지 버전 대조 | 미확인 | 외부 조회나 대상 앱 실행을 하지 않음 |
| OS별·브라우저별 지원 범위 | 미확인 | 이 문서가 명시한 Windows PowerShell 절차 외의 환경을 시험하지 않음 |

## 7. 학생이 직접 확인할 순서

기존 작업을 보존하고 새 PowerShell 창에서 다음 순서로 확인합니다.

1. 실제 `on-client/` 폴더에서 PowerShell을 열고, `npm run check`를 실행합니다. 완료 메시지와 종료 코드를 기록합니다. 이는 학생 모듈 문법 검사뿐입니다.
2. 같은 폴더에서 기본 실행 명령을 실행합니다. 정상 시작 문구, 출력된 주소와 포트를 기록합니다.
3. 그 주소를 브라우저에서 열어 화면이 표시되는지 확인합니다. 화면이 보이는 것과 실제 XDR·AI 연결 성공은 별도로 기록합니다.
4. 실행을 `Ctrl+C`로 종료하고, 같은 명령으로 다시 시작해 재실행되는지 확인합니다.
5. 포트 충돌이나 외부 연결 오류를 일부러 만들지 않습니다. 해당 장애를 실제로 보지 못했다면 확인 결과를 미확인으로 둡니다.
6. 실제 프로젝트 파일 경로와 실행 명령이 자신의 작업 폴더에 맞는지 대조합니다. 경로가 다르면 이 문서의 예시를 실제 폴더 위치에 맞춰 적용하되, 비밀 설정 경로나 내용을 공개하지 않습니다.

이 문서 작성 중에는 위 명령과 브라우저 확인을 실행하지 않았습니다. 직접 실행하지 않은 검사를 통과로 기록하지 않습니다.

## 8. 21·22단계 커밋과 원문 제출

커밋할 때는 학생 문서와 이번 단계의 코드 변경을 같은 커밋에 포함합니다. 이번 문서 변경만을 위해 코드 기능을 임의로 바꾸지는 않습니다. 기존에 커밋 준비 중인 변경이 있으면 먼저 내용을 확인하고 보존합니다. 커밋 해시를 문서에 미리 적지 않습니다.

21·22단계의 저장소 주소와 40자리 커밋은 과제 화면에서 직접 제출합니다. 비공개 저장소를 공개로 바꾸지 않습니다. 비공개 저장소 원문 제출이 필요한 경우:

1. 과제 화면의 **「비공개 저장소 원문 준비 방법」**을 펼치고 **「원문 전달 도구 받기」**를 사용합니다.
2. 안내된 ZIP은 프로젝트 밖에 압축 해제하고, JSON 출력물을 저장할 새 폴더도 프로젝트 밖에 만듭니다.
3. 제출할 프로젝트의 Git 최상위 폴더에서 PowerShell을 열고, 화면에 표시된 `student-source-cli.mjs` 명령을 따릅니다. 도구 경로·출력 파일 경로는 본인 PC의 실제 위치로, `--commit` 값은 제출할 40자리 커밋으로 지정합니다. 이 문서에서는 실제 경로와 커밋을 알 수 없으므로 명령을 추측해 적지 않습니다.
4. 생성된 JSON을 같은 단계의 **「비공개 저장소 원문 묶음」**에서 선택합니다. 저장소·커밋·단계를 다시 확인하고 제출합니다.
5. 원문 전달 완료는 AI 검토 통과와 다릅니다. 서버의 상태와 판정 설명을 확인합니다. 원문 전달만 실패했다면 기존 접수를 유지하고 **「원문만 다시 보내기」**를 사용합니다.

도구는 안내에 따라 커밋된 원문만 묶는 용도입니다. 학생 코드를 실행하거나 업로드하는 것으로 문서화하지 않습니다. 실제 도구 명령은 사용자의 포털 화면과 경로·커밋을 확인한 뒤에만 실행합니다.
