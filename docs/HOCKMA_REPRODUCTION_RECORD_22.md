# 호크마 22단계 새 환경 재현·버전 기록

> **기록 상태: 초안 / 재현 미완료 / 검증 중인 버전**  
> 이 문서는 학생이 실제로 확인한 결과를 남기기 위한 기록 양식과 현재 확인 가능한 사실을 구분합니다. 서버가 새 환경에서 실행했다는 증거, 공식 판정 또는 운영 인증이 아닙니다. 빈칸과 `미확인`을 실행 성공으로 해석하지 않습니다.

## 1. 대상 버전 식별 — 재현을 시작하기 전에 기록

원래 작업 폴더와 기존 기록은 보존합니다. 이 작업에서는 Git 명령을 실행할 수 없어 저장소 URL·브랜치·최종 커밋을 확인하지 못했습니다. 이전 대화에 저장소 주소와 서로 다른 단계 커밋이 언급되어 있지만, 현재 제출 대상의 원격·브랜치·40자리 해시인지 검증되지 않았으므로 최종 버전으로 전용하지 않습니다.

| 항목 | 현재 기록 | 확인 방법·상태 |
|---|---|---|
| 원래 작업 폴더 | `on-client` 앱 폴더가 선택된 프로젝트 안에 있음 | 파일 경로를 읽어 확인. 실제 PC의 절대 경로는 미확인 |
| 저장소 URL | 미확인 | 원래 프로젝트의 Git 최상위에서 `git remote -v`를 확인하되, 출력에 자격 정보가 있으면 공유하지 않음 |
| 제출 브랜치 | 미확인 | 실제 프로젝트 Git 최상위에서 `git branch --show-current` 실행 |
| 제출할 최종 커밋 | 미확인 — 40자리 해시를 기록해야 함 | `git rev-parse HEAD` 출력이 40자리인지 확인. 이전 단계의 짧은 해시를 대신 쓰지 않음 |
| 작업 트리 상태 | 미확인 | `git status --short`로 변경·미추적 파일을 확인. 결과를 확인하기 전 `reset`, `clean`, `restore`를 실행하지 않음 |
| 프로젝트 버전 | `package.json`에 `0.2.11`로 선언됨 | 현재 프로젝트 파일을 읽어 확인한 선언값이며, 제출 커밋과 일치하는지는 미확인 |
| 릴리스 표기 | **검증 중인 버전** | 실제 조치 집행 연결이 미완료이며 새 환경 재현도 미실행. `v1.0` 또는 운영 인증으로 표시하지 않음 |

**사용자가 기록할 값** (원래 폴더에서 확인한 뒤에만 채움):

```text
저장소 URL(비밀·자격 정보가 없는 형태): ______________________________
브랜치: ______________________________
최종 커밋(정확히 40자리): ____________________________________________
확인한 시각과 시간대: ______________________________
```

### 별도 폴더에서 같은 커밋 받기

아래는 사용자가 실제 URL·커밋을 확인한 뒤, 프로젝트 밖의 새 경로에 재현본을 만들 때 쓰는 예시 절차입니다. `<...>`는 확인된 값으로 바꿉니다. 기존 작업 폴더 안이나 그 위에 덮어쓰지 말고, 비어 있거나 아직 없는 별도 대상 폴더를 선택합니다. URL에 사용자명·토큰·비밀번호를 넣지 말고, 실행 결과를 공개 채팅에 붙일 때 자격 정보와 개인정보를 가립니다.

```powershell
# 원래 저장소의 Git 최상위 폴더에서 확인
 git status --short
 git branch --show-current
 git rev-parse HEAD
 git remote -v

# 새 PowerShell에서, 프로젝트 밖의 새 위치에 복제
 git clone <확인한-저장소-URL> <새-빈-폴더-경로>
 git -C <새-빈-폴더-경로> checkout --detach <확인한-40자리-커밋>
 git -C <새-빈-폴더-경로> rev-parse HEAD
 git -C <새-빈-폴더-경로> status --short
```

복제 뒤 `rev-parse HEAD`가 기록한 40자리 커밋과 정확히 같은지 확인합니다. 원격에 해당 커밋이 없거나 복제가 비공개 저장소 권한 때문에 실패하면 푸시·공개 전환·강제 옵션을 임의로 사용하지 않습니다. 과제 화면의 **「비공개 저장소 원문 준비 방법」**과 제공된 원문 전달 도구/수료 패키지 절차를 따릅니다. 도구 명령은 화면에서 받은 실제 경로와 값을 확인하기 전 만들어 내지 않습니다. 이 기록 작성자는 복제·체크아웃을 실행하지 않았습니다.

## 2. 새 환경 재현 절차 및 실행 기록

21단계 문서 `docs/HOCKMA_STUDENT_RUNBOOK.md`의 절차를 기준으로 하되, 복제한 폴더에서 관찰한 값만 결과 칸에 씁니다. 해당 설명서와 현재 `package.json`에는 기본 실행 명령, `npm.cmd run check`, `npm.cmd run demo`, Node.js 기준 `24.19.0`, 로컬 주소 `http://127.0.0.1:5189`가 기재되어 있습니다. 이들은 파일에서 읽은 설정·절차이지, 이 문서 작성 중 실제로 실행해 본 결과가 아닙니다. `package.json`에 외부 npm 의존성은 선언되어 있지 않으므로, 필요하지 않은 설치를 성공했다고 적지 않습니다.

| 4 | 문법 검사가 필요하면 `npm.cmd run check` 실행 | 검사 출력·종료 코드 미기록. 문법 검사도 미실행 | 미확인 |

## 4. 이동성·설정·의존성 확인

- 현재 `package.json`은 버전 `0.2.11`, Node.js `24.19.0`, `start`/`demo`/`check` 스크립트를 선언하며 외부 `dependencies`와 `devDependencies`는 비어 있습니다. 이는 현재 파일에서 확인한 값이며, 정확한 제출 커밋의 값은 커밋 확인 뒤 대조해야 합니다.
- 21단계 학생 설명서는 절대 로컬 작업 경로를 실행 요건으로 삼지 않고 프로젝트 상대 경로를 사용합니다. 외부 비밀 설정 값이나 인증 파일은 복제본에 복사하지 않습니다.
- 저장소 문서가 기본 실행과 demo의 차이, 연결 설정의 별도 준비 필요성을 설명합니다. 실제 접근 제어·XDR·AI 게이트웨이 주소 및 새 환경의 연결 성공은 확인되지 않았습니다.
- 설치·실행 명령은 현재 읽은 `package.json`과 실행 설명서에 맞춰 기록했습니다. 실제 새 폴더에서 확인하기 전까지 설치·실행 가능성은 보장하지 않습니다.

## 5. 데이터 보존·백업·복원 계획과 제한

1. 재현 전 원래 작업 폴더와 기존 Git 기록을 그대로 둡니다. 재현은 별도 폴더에서 하고 원래 폴더에 `git clean`, `reset --hard`, 삭제, 덮어쓰기 또는 강제 checkout을 하지 않습니다.
2. 현재 최종 커밋과 작업 트리 상태를 먼저 기록합니다. 저장되지 않은 작업이 있으면 원본 파일을 보존하고, 무엇을 백업할지 확인하기 전에 재현 폴더로 옮기지 않습니다.
3. 백업이 필요하면 원본 폴더 전체를 다른 안전한 위치에 복사하기 전에, 인증서·토큰·비밀번호·개인정보·런타임 데이터의 보관 규칙과 제외 대상을 확인합니다. 자격 파일은 Git·제출 묶음·문서에 포함하지 않습니다. 이 문서 작성자는 실제 백업을 만들거나 복원하지 않았습니다.
4. 현재 읽은 `src/actions/store.mjs`는 호출자가 제공한 기존 SQLite DB 경로를 확인하고, 조치 intent/state/audit 테이블을 추가하며 intent/audit 이력 변경을 제한하는 코드를 포함합니다. 하지만 실제 사용 DB 경로, 운영 데이터 위치, 백업 일정, 복원 절차, 현재 사용자 데이터의 존재 여부는 이 기록에서 확인하지 않았습니다. 이 모듈의 코드만으로 전체 앱 데이터가 SQLite에 저장된다고 단정하지 않습니다.
5. 실제 데이터베이스나 서버 로그를 백업·복원해야 한다면 운영 담당자가 승인한 문서와 경로를 먼저 확인합니다. 설정 파일을 무작정 복사하거나 임의의 파일·DB 경로를 만들어 내지 않습니다. 확인된 보존·복원 절차가 없으면 해당 항목을 미확인으로 남깁니다.

| 데이터 범위 | 현재 확인 | 보존/복원 기록 |
|---|---|---|
| 소스와 Git 이력 | 앱 파일과 프로젝트 문서를 읽음. 현재 branch/commit/status는 미확인 | 원본 보존, 별도 복제. 새 clone 및 원문 복제 미실행 |
| 인증·비밀 설정 | 문서에서 프로젝트·Git·제출 밖 보관 원칙을 확인 | 복사하지 않음. 위치·백업은 미확인 |
| 이벤트·서버 데이터 | 이 환경에서 데이터 저장 위치를 확인하지 않음 | 백업·복원 미실행, 공식 경로 미확인 |
| 조치 감사 저장소 | 소스에 명시적 DB 경로 기반 저장 모듈이 있음 | 실제 연결·DB·복구 수행 여부 미확인 |

## 6. 지원 범위·미해결 사항·이 기록의 한계

- 이 기록은 **검증 중인 버전**의 기록 초안입니다. 19단계 실제 조치 실행 연결은 미완료이고, 이 기록 작성자는 새 커밋을 별도 폴더에서 실행하지 않았습니다.
- demo 화면은 예제 데이터입니다. 실제 사용자 또는 실제 접근 제어/XDR 시스템과의 연결 성공이라고 쓰지 않습니다.
- 재현 기록은 학생의 관찰·진술입니다. 서버가 새 환경을 실행했다는 뜻이 아닙니다. AI의 원문 검토 역시 실행 성공의 증명은 아닙니다.
- 22단계 검토는 같은 최종 커밋의 코드·README·설정 설명·데이터 보존 계획·학생의 재현 기록이 일치하는지 보는 원문 검토입니다. 운영 환경 인증이나 `v1.0` 자동 인증이 아닙니다.
- 이 기록은 프로젝트 파일과 기존 실행 설명서를 읽고 작성했습니다. 명령 실행, Node.js 버전 확인, Git 원격/브랜치/커밋 확인, clone, 브라우저 실행, 데이터 백업·복원, 공식 제출은 하지 않았습니다.
